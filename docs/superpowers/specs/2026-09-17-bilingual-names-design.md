# تصميم: الأسماء ثنائية اللغة `{ar, en}` + النسب المحسوب حيًّا

**التاريخ:** 2026-09-17
**الحالة:** مُعتمَد مبدئيًا (بانتظار مراجعة المالك للمواصفة)
**المرحلة:** 1b — الأسماء (الثابت #2)

## المشكلة والهدف

1. الأسماء تُخزَّن كنص عربي مفرد، بينما الثابت #2 يفرض `{ar, en}` — والإنجليزية جوهر
   تميّز التطبيق (جمهور المهجر).
2. الاسم يُخزَّن كـ**نسب كامل جاهز** («خالد محمد أمين أحمد الوزير»)، لا كاسم أول. لذلك
   تعديل اسم الأب **لا يسري** على الأبناء (مشكلة أبلغ عنها المالك).

الحلّ يعالج الاثنين معًا: نخزّن **الاسم الأول (المقطع الخاص) بلغتين**، ونحسب النسب
الكامل **حيًّا** عند العرض بالمرور صعودًا لسلسلة الآباء.

## القرارات المُتّفق عليها (عصف ذهني)

- الاسم الإنجليزي: **نقل حرفي تلقائي (قابل للتعديل) + إلزامي**.
- الترحيل: **نقل حرفي تلقائي الآن** لكل الأسماء الموجودة.
- النسب: **محسوب حيًّا** من الاسم الأول (لا يُخزَّن كنص جاهز).

## نموذج البيانات

`person.name`: نص → **`{ar, en}`** يحمل **المقطع الخاص بالشخص فقط** (الاسم الأول)،
لا النسب الكامل. الجذر يحمل «الاسم + اللقب» (مثل `{ar:'أحمد الوزير', en:'Ahmed Alwazir'}`)
لأن اللقب يورَّث من الجذر.

`state.familyName`: نص → `{ar, en}`.

- **الثابت #1:** `personId` ثابت — لا علاقة له بالاسم.
- لا نخزّن النسب الكامل مطلقًا؛ يُشتقّ دائمًا.

### حساب النسب حيًّا

```
fullName(p, lang):
    parts = []
    cur = p
    guard = 0
    while cur and guard++ < 64:
        parts.push( own(cur, lang) )      // المقطع الخاص باللغة المطلوبة
        cur = fatherOf(cur)               // نفس منطق kinship: الأب حسب نوع الوالد
    return parts.join(' ')
```

- `own(p, lang)` = `p.name[lang]` مع بديل للّغة الأخرى إن فرغت (لا مقطع فارغ).
- `fatherOf` يُعاد استخدامه من منطق النسب الحالي (الأب = الذكر في الزوجين).
- تعديل اسم أي جدّ يظهر فورًا في كل الذرّية لأن الاسم محسوب لا مخزَّن.
- الأداء: O(العمق) لكل شخص؛ لمئات الأفراد لا يُذكر. تُخزَّن نتائج العرض مؤقتًا لكل رسم
  إن لزم.

## محرّك النقل الحرفي — ملف جديد `translit.js`

- `window.ftTranslit('محمد')` → `'Mohammed'` (مثل `kinship.js`: كلاسيكي، قابل للاختبار في node).
- قاموس للأسماء العربية الشائعة (~150: محمد، أحمد، علي، فاطمة، عبدالله، إبراهيم، يوسف،
  عمر، خالد، حسن، حسين، مريم، عائشة، خديجة، زينب…) لكل كلمة.
- نقل حرف-بحرف احتياطي لغير الشائع (إزالة التشكيل، خريطة حروف، تهيئة أول حرف).
- لكل كلمة على حدة، ثم تُجمع بمسافات.

## واجهة العرض — دالتان مركزيتان

- `fullNameOf(person)` — النسب الكامل باللغة الحالية (المحسوب).
- `firstNameOf(person)` — المقطع الخاص باللغة الحالية.
- **كل** مواضع عرض الاسم (~١٢ موضعًا: البطاقة، القرابة، الحوارات، التلميحات، البحث،
  اسم ملف التصدير، عنوان الشجرة) تمرّ عبر `fullNameOf` (أو `firstNameOf` حيث يناسب).

## نموذج إدخال الشخص

- حقلان: **الاسم الأول (عربي)** و **First name (English)**.
- عند كتابة العربي يُملأ الإنجليزي تلقائيًا عبر `ftTranslit`، **ما لم** يعدّله المستخدم
  يدويًا (نتتبّع «لُمس»).
- **معاينة النسب حيّة باللغتين** (نستخدم `fullName` على أب-افتراضي = الأب المحسوب من
  `coupleContext`).
- **إلزامي:** يُمنع الحفظ إن فرغ العربي أو الإنجليزي (تنبيه).
- يعمل فوق إصلاح `coupleContext` الحالي: الطفل يُنسب للأب ويُعلَّق على عضو النسب.

## الترحيل التلقائي (مرة واحدة)

دالة مخصّصة `migrateNames(state)` تعمل عند كل تحميل (محلي وسحابي) وتتخطّى إن كانت
الأسماء كائنات أصلًا. **مرحلتان** لتفادي ترتيب الأب/الابن:

1. **لقطة:** اجمع النصوص القديمة كاملةً في خريطة `{id: fullOld}` **قبل** أي تحويل
   (وإلا فقد يصير الأب كائنًا قبل أن يحتاجه الابن).
2. **تحويل:** لكل شخص:
   - **المقطع الخاص العربي** = `fullOld[id]` بعد نزع لاحقة نسب الأب
     `' ' + fullOld[fatherId]` (إن وُجد أب؛ وإلا فالنص كما هو — يشمل اللقب للجذر).
   - `name = { ar: ownAr, en: ftTranslit(ownAr) }`.
3. `familyName` نص → `{ ar: fam, en: ftTranslit(fam) }`.

(نستبدل معالجة `name` النصية داخل `migratePerson` بهذه الدالة؛ يبقى `migratePerson`
لبقية الحقول.)

## الأمان

- لا تغيير أمني (بيانات فقط). قواعد Firestore لا تتحقق من شكل الأسماء، واختبار القواعد
  يستخدم `familyName:{ar,en}` أصلًا. لا حاجة لمراجعة أمنية بوكيل مختلف (قاعدة المؤسسة #2
  تُطلق على الأمن فقط).

## `kinship.js` لا يتغيّر

يستخدم المعرّف والنوع والأبوّة فقط — لا الاسم في منطقه. عرض أسماء طرفَي القرابة في
`app.js` يمرّ عبر `fullNameOf`.

## الاختبار

- **وحدات `translit.js`** (node): أسماء شائعة + نقل حرفي احتياطي + جُمَل متعددة الكلمات.
- **وحدات حساب النسب** (node، دالة نقية على خريطة الأشخاص): سلسلة ٣ أجيال، وتعديل جدّ يظهر
  في الذرّية، وباللغتين.
- **يدوي في المتصفح:** إضافة شخص (املأ تلقائي + إلزام)، تبديل EN يعرض الأسماء الإنجليزية،
  نسب باللغتين، تعديل اسم أب يحدّث الأبناء فورًا، ترحيل الشجرة الحالية.

## الملفات المتأثرة

- `translit.js` (جديد) + تحميله في مُحمِّل `index.html` قبل `app.js` (مثل `kinship.js`).
- `app.js`: `fullNameOf`/`firstNameOf`/`ownName` + حساب النسب حيًّا؛ نموذج الإدخال بحقلين +
  نقل تلقائي؛ `newPerson`/`migratePerson`/`updatePerson` بالنموذج الجديد؛ `buildFullName`
  يُستبدل بالحساب الحيّ؛ تحديث ~١٢ موضع عرض؛ البحث يطابق النسب المحسوب.
- `cloud.js`: `familyName` صار كائنًا (setDoc يتعامل مع الكائنات؛ لا تغيير جوهري).

## خارج النطاق (لاحقًا)

- تحرير المقطع الخاص وحده مقابل النسب (نحرّر المقطع الخاص فقط؛ النسب محسوب).
- نقل حرفي خادمي أدقّ.
