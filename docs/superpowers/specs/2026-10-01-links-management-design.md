# إدارة روابط العائلة — مواصفة التصميم

> **الحالة:** معتمدة · **التاريخ:** 2026-10-01 · **المشروع:** ٣-ج من مسار «ربط العائلات»
> **يعتمد على:** ٢ (بروتوكول الربط) + ٣-أ (العرض) — منشوران. **يكمله:** ٣-ب (المشاركة) لاحقاً.

## ١. الهدف

منح مالك الشجرة **رؤية وتحكّماً** في: (أ) طلبات الربط المعلّقة التي أنشأها، و(ب) من يملك
حقّ رؤية شجرته (الزوّار). مع **تنظيف تلقائي** للطلبات التي أدّت غرضها — لإيقاف تراكم مستندات
الروابط المكرّرة من إعادة استخدام الرمز.

**لماذا:** رمز طلب الربط المُشارَك يبقى صالحاً للأبد حتى يحذف المالك الطلب؛ وإعادة فتح الرابط
تولّد روابط مكرّرة. هذا المشروع يغلق الثغرة ويمنح الشفافية.

## ٢. الجمهور والسياق

PWA + ويب، مستودع **عام**، Firebase **Spark المجاني**.

## ٣. الثوابت المحترمة

- **مصدر الصلاحية `trees/{treeId}/members/{uid}` فقط** · **`personId` ثابت** · **حذف الشجرة ممنوع**.
- **`t()` للطريق الوحيد للنص** — الكود الجديد يلتزم (بخلاف `showMembers` القديمة).
- **كل شجرة سيادية** — المالك يلغي طلباته ويطرد زوّاره دون إذن أحد.

## ٤. القرار المحوري: لا تغيير في القواعد

كل العمليات مسموحة أصلاً — **لا تعديل على `firestore.rules`**:
- `linkRequests`: `list: if isOwner` + `delete: if isOwner` (من المشروع ٢).
- `viewers`: `list: if isOwner` + `delete: if isOwner || viewerUid==uid()` (من المشروع ٣-أ).

مشروع **عميل بالكامل**. لا توسيع لسطح الهجوم. (مرتبط بالصلاحيات فيُراجَع، لكن أخفّ بلا تغيير قواعد.)

## ٥. نموذج البيانات (مجموعات قائمة، بلا جديد)

- `trees/{t}/linkRequests/{token}` — الطلبات المعلّقة (تُسرَد وتُحذف).
- `trees/{t}/viewers/{uid}` — من يرى شجرتي (يُسرَد ويُطرَد). الحقول: `{grantedBy, viaRequest?, remoteTreeId, at}`.
- `trees/{t}/links` — لكشف «الطلب أنتج رابطاً» (`link.viaRequest === req.token`) للتنظيف التلقائي، ولمطابقة `remoteTreeId` باسم العائلة في العرض.

## ٦. المنطق (cloud.js)

- `listLinkRequests()` → `getDocs(linkRequests)` → `[{token, localPersonName, localFamilyName, localPersonId, createdAt}]` (مالك فقط).
- `deleteLinkRequest(token)` → `deleteDoc(linkRequests/{token})`.
- `listTreeViewers()` → `getDocs(viewers)` → `[{uid, remoteTreeId, grantedBy, at}]` (مالك فقط).
- `revokeViewer(uid)` → `deleteDoc(viewers/{uid})`.
- **التنظيف التلقائي** (مالك فقط، بعد `loadLinks`): اقرأ `linkRequests`؛ لكل طلب موجود رابط
  `currentLinks.some(l => l.viaRequest === req.token)` → احذف الطلب (أدّى غرضه). أفضل جهد،
  يسجّل الأخطاء ولا يكسر التدفّق. *(مِنح الزوّار محدَّدة بالمعرّف فيُكتب فوقها — لا تتكرّر؛
  التكرار في الروابط فقط.)*

## ٧. الواجهة (app.js)

- **المدخل:** زر «🔗 إدارة روابط العائلة» في قائمة `menuBtn` (للمالك فقط: `window.__ftCloud.isOwner()`).
- **الورقة** (`showLinksManager` في cloud.js، تبني `#sheetBody`، نصوص عبر `t()/tf()`) بقسمين:
  1. **طلبات ربط معلّقة:** لكل طلب «‹اسم الشخص› — عائلة ‹الاسم›» + زمن نسبي + زر «إلغاء الطلب».
     فارغ ← «لا طلبات معلّقة».
  2. **من يمكنه رؤية شجرتك:** لكل زائر اسم العائلة (نطابق `viewer.remoteTreeId` مع
     `remoteFamilyName` من `listLinks()`؛ وإلا «عائلة مرتبطة») + زر «إلغاء الوصول».
     فارغ ← «لا أحد يرى شجرتك».
- بعد كل حذف/طرد يُعاد بناء القسم (أو إعادة فتح الورقة). تصميم ترابي هادئ متّسق مع البقية.

## ٨. خارج النطاق

المشروع ٣-ب (المشاركة: لحظات/سجل مشترك — وقرار كشف الخاص مقابل مساحة مشتركة).

## ٩. الاختبار

1. **منطق نقيّ** (node): اختيار الطلبات القابلة للتنظيف من (قائمة طلبات + قائمة روابط) عبر
   مطابقة `viaRequest` — دالة صغيرة قابلة للاختبار.
2. **قواعد:** لا تغيير؛ القواعد القائمة (list/delete للمالك) مغطّاة باختبارات ٢ و٣-أ الحالية.
3. **الواجهة** في المعزل: سرد الطلبات/الزوّار بمحاكاة `__ftCloud`، الحذف/الطرد يستدعيان الدوال،
   والتنظيف التلقائي يحذف الطلب المطابق فقط.

## ١٠. المخاطر والتخفيف

| الخطر | التخفيف |
|---|---|
| التنظيف يحذف طلباً ما زال مطلوباً | يحذف فقط طلباً له رابط مطابق بـ`viaRequest` (أدّى غرضه فعلاً)؛ الضرر محدود (الطلب قابل لإعادة الإنشاء) |
| طرد زائر لا يحذف الرابط | مقصود — السيادة: المالك يقطع الرؤية؛ وسم الرابط لدى الطرف الآخر يبقى (يُكتشف عند العرض) |
| نص غير مترجم | الكود الجديد يلتزم `t()` حصراً |
| تغيير متعلّق بالصلاحيات | مراجعة وكيل مختلف (أخفّ، بلا تغيير قواعد) قبل الإعلان |

## ١١. ترتيب البناء (عناوين — التفاصيل في الخطة)

1. منطق نقيّ: `requestsToGC(requests, links)` + اختبار node.
2. cloud.js: `listLinkRequests`/`deleteLinkRequest`/`listTreeViewers`/`revokeViewer` + التنظيف التلقائي في `loadLinks`.
3. cloud.js: `showLinksManager` (الورقة) + تسجيلها في `__ftCloud` + مفاتيح `t()`.
4. app.js: زر القائمة (للمالك) + ربطه.
5. تحقّق معزول + مراجعة (أخفّ) + نشر (دمج ودفع؛ لا نشر قواعد — لا تغيير فيها).
