# تصميم: «اليوم في العائلة» — تذكيرات المواليد والذكرى

تاريخ: 2026-09-23

## الهدف
بطاقة في الشاشة الرئيسية تُقرّب أفراد العائلة عاطفيًّا عبر عرض **مواليد الأحياء**
و**ذكرى الراحلين** القريبة، بلغتين (عربي/إنجليزي) وبعرض التقويمين (ميلادي + هجري).
تستفيد من الحقول الموجودة `birthDate` و`deathDate` دون أي تغيير في مخطط البيانات.

## القرارات (من جلسة العصف الذهني)
- **المناسبات:** مواليد الأحياء + ذكرى وفاة الراحلين. **بلا ذكرى زواج** (لا حقل لها، غير مطلوبة).
- **النطاق الزمني:** اليوم + القادم خلال **٣٠ يومًا**.
- **التقويم:** المطابقة بالميلادي (يوم/شهر كما أُدخِل التاريخ)، مع **عرض** الهجري بجانبه.
- **التفاعل:** الضغط يفتح ملف الشخص؛ وزر سريع «🎉 هنّئ» (للأحياء) / «🤲 ادعُ له»
  (للراحلين) يفتح «لحظات العائلة» برسالة جاهزة يراجعها المستخدم وينشرها بنفسه.
- **الحالة الفارغة + الحثّ:** عند غياب المناسبات تظهر دعوة لإضافة التواريخ، مع زر يفتح
  **قائمة إضافة سريعة** لأفراد بلا تاريخ ميلاد، أمام كلٍّ منتقي تاريخ يُحفظ فورًا.
- **خارج النطاق (YAGNI):** إشعارات Push (لاحقًا)، ذكرى الزواج.

## المكوّنات (وحدات صغيرة ومنفصلة)

### 1. `occasions.js` — محرّك المناسبات (منطق صرف، بلا DOM)
دالة نقيّة قابلة للاختبار في Node، على غرار `kinship.js`:
```
window.ftOccasions(people, todayDate, windowDays) -> [occasion]
```
حيث `occasion = { id, type:'birthday'|'memorial', dateStr, daysUntil, turningAge|yearsSince }`.
- لكل فرد: إن كان حيًّا وله `birthDate` → مناسبة `birthday`؛ إن كان متوفّى (`deathDate`)
  وله `deathDate` → مناسبة `memorial`.
- `daysUntil`: أقرب تكرار سنوي (يوم/شهر) من `todayDate` ضمن `[0, windowDays]`؛ خارج
  النطاق يُستبعد. معالجة **29 فبراير** (يقع على 28 فبراير في السنوات غير الكبيسة).
- `turningAge` = العمر الذي سيُتمّه (للمواليد، إن توفّر عام الميلاد)؛ `yearsSince` =
  عدد السنوات منذ الوفاة (للذكرى).
- الفرز: `daysUntil` تصاعديًّا؛ اليوم (`0`) أولًا.
- لا اعتماد على `state` أو `t()` — يُمرَّر كل شيء كوسائط، ليبقى نقيًّا وقابلًا للاختبار.

### 2. بطاقة العرض في `renderHome` (app.js)
- تُبنى بطاقة أعلى الرئيسية بعنوان `t('todayTitle')` («🎉 اليوم في العائلة»).
- تستدعي `window.ftOccasions(state.people, new Date(), 30)`، ثم تقسّم النتائج إلى
  «اليوم» (daysUntil==0) و«قريبًا».
- كل صف: أيقونة (🎂/🕊) + الاسم الكامل + وصف («عيد ميلاده اليوم» / «بعد N يوم» /
  «ذكرى وفاته») + التاريخ (ميلادي — هجري عبر `hijriText`) + زر التهنئة/الدعاء.
- الصف `data-profile="<id>"` (يُعيد استخدام مُوجِّه الملف الموجود) وزر التهنئة
  `data-greet="<id>"`.
- كل النصوص عبر `t()` (ثابت #3).

### 3. الحالة الفارغة + قائمة إضافة التواريخ السريعة (app.js)
- إن لم توجد مناسبات ضمن النطاق: تعرض البطاقة دعوة `t('todayEmpty')` + زر
  `t('todayAddDates')`.
- الزر يفتح **صحيفة (sheet)** «إضافة تواريخ الميلاد» تُدرِج كل فرد بلا `birthDate`،
  أمام كلٍّ `input[type=date]`؛ عند تغيير القيمة تُحفظ مباشرةً في `state.people[id].birthDate`
  ثم `scheduleSave()` (يتزامن سحابيًّا بعد إصلاح المزامنة) و`renderHome()`.
- تُعاد بناء القائمة بعد كل حفظ (يختفي من أضيف تاريخه)، أو تُترك حتى الإغلاق — نختار
  **الإبقاء حتى الإغلاق** لتفادي القفز البصري، مع علامة «✓» بجانب من حُفظ.

### 4. زر التهنئة/الدعاء → «لحظات العائلة»
- عند الضغط: يفتح تبويب `moments` عبر `__ftShowTab('moments')` ويملأ `#momentText`
  برسالة جاهزة من `t()`:
  - مولود: `tf('greetBirthday', {name})` («كل عام و{name} بخير 🎉»).
  - ذكرى: `tf('greetMemorial', {name})` («اللهم ارحم {name} وأسكنه فسيح جناته 🤲»).
- **لا نشر تلقائي** — يظهر النص في مربّع الإنشاء ليراجعه المستخدم ويضغط «نشر» بنفسه.

## تدفّق البيانات
`renderHome` → `ftOccasions(people, today, 30)` → تقسيم/عرض → ضغط:
- صف → `openProfile(id)`.
- زر تهنئة → فتح moments + تعبئة النص.
- زر «أضف تواريخ» → صحيفة القائمة السريعة → عند الإدخال: تحديث `state` + `scheduleSave` + إعادة عرض.

## معالجة الأخطاء والحواف
- فرد بلا تاريخ صالح → يُتجاهل بهدوء (لا يُدرَج).
- تاريخ غير قابل للتحليل → يُتجاهل (لا يكسر البطاقة).
- 29 فبراير → يُطابَق على 28 فبراير في السنة غير الكبيسة.
- متوفّى له `birthDate` أيضًا → يُدرَج كـ**ذكرى وفاة فقط** (لا عيد ميلاد للراحل).
- لا مناسبات ولا أفراد بلا تاريخ → دعوة عامة لإضافة التواريخ.

  حساب العمر/سنوات الذكرى، تجاهل التواريخ الفارغة/غير الصالحة.

## الأمن والبيانات
- **لا حقول جديدة، ولا تغيير في `firestore.rules`** — قراءة فقط لحقول موجودة، والكتابة
  الوحيدة (إضافة تاريخ ميلاد) تمرّ عبر مسار الحفظ القائم (المُصلَح `updateDoc`).
- ليست تغييرًا أمنيًّا؛ لا حاجة لمراجعة قاعدة المؤسسة #2. (تبقى مراجعة جودة عادية.)
