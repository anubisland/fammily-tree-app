# تصميم: التواريخ (ميلادي + هجري) وصفحة تفاصيل الشخص

**التاريخ:** 2026-09-18
**الحالة:** مُعتمَد مبدئيًا (بانتظار مراجعة المالك للمواصفة)
**المرحلة:** 2 — إثراء التطبيق

## الهدف والسياق

إثراء التطبيق بلمسة احترافية دون أي خطر على البيانات الحسّاسة (الأسماء). عنصران
مترابطان:
1. **التواريخ:** تاريخ الميلاد موجود؛ نضيف تاريخ الوفاة، ونعرض كل تاريخ **بالميلادي
   والهجري** معًا (الثابت #7: التقويم الهجري افتراض للجمهور العربي)، مع العمر ومدّة
   الحياة، ومؤشّر «متوفّى».
2. **صفحة تفاصيل الشخص:** تُفتح بالضغط على جسم الكارت، وتعرض كل معلومات الفرد وأقاربه
   مع تنقّل بينهم.

**مبدأ حاكم (تعلّمناه بألم):** كل تغيير **إضافي وغير مدمِّر**. لا مساس بحقل `name`
ولا هجرة بيانات. نأخذ نسخة احتياطية قبل النشر.

## نموذج البيانات

- إضافة حقل **`deathDate`** (نص تاريخ ميلادي `YYYY-MM-DD`، أو `null`) إلى الشخص.
- `newPerson` يضيف `deathDate: null`. `migratePerson` يضيف
  `if(p.deathDate === undefined) p.deathDate = null;` (متوافق مع البيانات القديمة).
- لا تغيير آخر في النموذج. **الثابت #1** (`personId`) و**#2** (`name={ar,en}`) سليمان بلا مساس.

## التقويم والتواريخ — دوال نقية (بلا مكتبات)

كلها في `app.js`، مبنية على `Intl.DateTimeFormat` المدمج:

- `parseDate(str)` → كائن `Date` صالح أو `null` (تحقّق: `!isNaN(d)`).
- `gregText(str)` → التاريخ ميلاديًا منسّقًا حسب `state.lang` (مثل «14 مارس 1980» / «14 Mar 1980») عبر `Intl.DateTimeFormat(lang, {day,month,year})`.
- `hijriText(str)` → التاريخ هجريًا عبر `Intl.DateTimeFormat('ar-SA-u-ca-islamic-umalqura', {day:'numeric',month:'long',year:'numeric'})` ثم إلحاق «هـ». (للإنجليزية: `en-US-u-ca-islamic-umalqura` + " AH".)
- `fmtDate(str)` → `gregText(str) + ' — ' + hijriText(str)`؛ فراغ إن كان `str` فارغًا/غير صالح.
- `ageYears(birthStr, refStr?)` → العمر بالسنين الميلادية حتى `refStr` (أو اليوم)؛ `null` إن تعذّر.
- `lifespanText(birthStr, deathStr)` → «عاش N سنة» / "lived N years" إن توفّر التاريخان.

**ملاحظة توافق:** `Intl` بتقويم `islamic-umalqura` مدعوم في متصفحات الجوال الحديثة
(Chrome/Safari)؛ عند غياب الدعم يُرجع `hijriText` سلسلة فارغة بأمان (try/catch) فيظهر
الميلادي وحده — لا كسر.

## نموذج التعديل (openPersonForm — وضع edit)

- نُبقي حقل الميلاد، ونضيف تحته حقل **الوفاة**: `<input type="date" id="pf_death">`
  بقيمة `target.deathDate||''`، اختياري.
- عند الحفظ: `deathDate: document.getElementById('pf_death').value || null`.
- `updatePerson` يحفظ `deathDate` (وتُضاف «تاريخ الوفاة» إلى سجل التغييرات إن تغيّر).

## الكارت — مؤشّر «متوفّى»

- إن كان `deathDate` مضبوطًا: يُضاف صنف `.deceased` للكارت + وسم صغير أنيق **«رحمه الله»**
  (إنجليزيًا «In memory») تحت الاسم، وسطر مدّة الحياة إن توفّر التاريخان
  (`ageYears(birth) → 'وُلد–تُوفّي'` مختصر). تنسيق هادئ (لون رمادي خفيف/شريط)، دون إثقال
  الكارت — التفاصيل الكاملة في الصفحة.
- الأحياء: كما هو (🎂 العمر إن توفّر الميلاد).

## صفحة تفاصيل الشخص — `openProfile(id)`

**الفتح:** في معالِج نقر `#treeRoot`: إذا لم نكن في وضع القرابة، ولم يكن الهدف زرّ إجراء
(`[data-act]`)، وكان داخل `.card` له `dataset.id` → `openProfile(id)`. (نضيف شرطًا قبل
`var btn = e.target.closest('[data-act]')`.)

**العرض:** ورقة سفلية (`openSheet`) بمحتوى مبني بسلاسل HTML، **كل نص عبر `t()`، وكل قيمة
مستخدم عبر `escapeHtml`**:
- رأس: الصورة (أو أيقونة النوع)، **الاسم الكامل** باللغة الحالية (`fullNameOf`)، وتحته
  الاسم باللغة الأخرى، وبادج الجيل.
- **التواريخ:** «الميلاد: `fmtDate(birth)`» + «العمر: N» (للأحياء)؛ للمتوفّى: «الوفاة:
  `fmtDate(death)` — رحمه الله» + «مدّة الحياة: N سنة».
- «الإقامة: …» إن وُجدت.
- **الأقارب** (كل عنصر زر يفتح `openProfile` للقريب): الأب (`fatherOfPerson`)، الأم
  (`motherOfPerson` — يُضاف مثل الأب لكن للأنثى)، الزوج/الزوجات (`spouseIds`)، الأبناء
  (`childrenIds`). الأسماء عبر `fullNameOf`. تُخفى الأقسام الفارغة.
- **أزرار:** «تعديل» (`openPersonForm('edit', id)`)، «إضافة ابن» (`openPersonForm('child', id)`)،
  «القرابة» (`startKinship` مع تحديد هذا الشخص كطرف أول — أو بدء عادي). تظهر أزرار التعديل/الإضافة
  فقط عند `canEditCloud`.
- **التنقّل:** الضغط على قريب يستدعي `openProfile(otherId)` (يعيد بناء نفس الورقة) — تنقّل سلس.

**دالة مساعدة جديدة:** `motherOfPerson(p)` (مرآة `fatherOfPerson`: الوالد إن كان أنثى،
وإلا زوجة الوالد إن كانت أنثى).

## الترجمة (i18n)

مفاتيح جديدة عبر `t()`: `birthLabel` (موجود)، `deathLabel`، `profileAge`، `profileLifespan`،
`inMemory` («رحمه الله» / «In memory»)، `relFather`، `relMother`، `relSpouse`، `relChildren`،
`profileEdit`، `profileAddChild`، `profileKinship`. لا نصوص عربية ثابتة.

## الاختبار

- **node (دوال نقية):** `fmtDate` يُخرج ميلاديًا+هجريًا لتاريخ معروف؛ `ageYears` صحيح؛
  `lifespanText` صحيح؛ فراغ/غير صالح → سلسلة فارغة بلا استثناء. (ملف `scripts/dates.test.cjs`
  عبر تصدير الدوال تحت حارس node الموجود، أو نسخة قائمة بذاتها.)
- **المتصفح:** فتح الصفحة بالضغط على كارت؛ ظهور التقويمين؛ متوفّى يُظهر «رحمه الله» ومدّة
  الحياة؛ روابط الأقارب تنقل صحيحًا؛ التعديل يحفظ تاريخ الوفاة ويظهر مؤشّر المتوفّى؛
  فحص EN. تحقّق أن نقر أزرار الإجراءات لا يفتح الصفحة (تعارض).
